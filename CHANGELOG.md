## [0.3.1] - 2026-10-25

### Added
- Simulation settings (⚙): an **Integration** field picks Gecko's integration method, the `.ipes` `solverType`: backward Euler (0, Gecko's default), trapezoidal (1) or Gear/BDF2 (2). It shows the open file's method and applies when the run starts, like Δt and end time: Gecko only reads `solverType` when it opens a file, so if the run asks for another one the simulator rewrites the line in the run's copy of the circuit and Gecko reopens it; Save then writes it into the circuit. The run's `meta` (`solver`) and `resumo.md` record the method, and the scope's Compare warns when A and B used different ones. `simu/validacao/buck_solvers.py` runs the same buck with all three: each matches its own recurrence to 1.6e-8 A, and after the diode blocks only the trapezoidal method rings (±0.33 V on v_sw, `simu/validacao/dados/solver_buck_trapezio.png`) (#116).
- Thermal network and simple losses from the screen: Rth, Cth, DT, HEAT-SOURCE, Pv and TREF get their terminals where Gecko puts them (thermal wires connect and are checked like the others, drawn in orange); the Pv panel picks the switch or diode it heats (shown as "♨ IGBT.1"), TEMP measures between two thermal labels and FLOW reads a Pv's total, conduction or switching loss (`losscomp`, saved in the file), with automatic names (`Tj_IGBT1`, `Pv_IGBT1`, `Psw_IGBT1`) for the scope and `m[...]`, also inside subcircuits; semiconductors show a **Losses** section (uF, rON, k_on, k_off, uK) and warn when no Pv uses them. New example `exemplo_buck_termico` (buck with IGBT and diode losses heating an Rth–Cth network), checked by hand against Gecko's formulas (`termica_api`, `termica_tela`) (#119).
- Two examples with the control all in Gecko blocks, no Python: **Buck — PI in blocks** (`exemplo_buck_pi_blocos`: the `exemplo_buck` plant with a voltage loop SUB → PI → LIMIT 0…0.95 → triangle carrier → GE → GATE; the reference steps from 24 to 30 V at 20 ms and a second 10 Ω load switches in at 40 ms, both from the TIME block; Kp = 0.005, Ki = 10 from the LC plant, crossover ≈ 480 rad/s below the resonance: v_o within 0.1 % of the reference, ≈ 1 % overshoot on the reference step) and **DC motor — PI in blocks** (`exemplo_motor_cc_blocos`: the `exemplo_motor_cc` plant and gains, speed P + INT with integration only near the reference (the PI block has no anti-windup) → LIMIT ±15 A → current PI + back-EMF feedforward → LIMIT 0…0.98 → PWM; 1000/1000/1500 rpm like the Python one, Tel = T_load + fr·ω, overshoot 1.3 % / 0.9 % against 1.8 % / 0.6 %). Both open with a default scope layout (pt/en); `exemplos_api` checks the steps and compares the motor with the Python example (#136).
- Control blocks: a newly created block gets values that work instead of Gecko's (a PI of negative gain `r0 = a1 = −1`, a hysteresis of `h = −1`, an integrator clamped to ±1, PT1/PT2 with `T = 1 s`, a Sliding DFT of 10 µs at 500 Hz): **PI** Kp (`r0`) = 1 and Ki (`a1`) = 100 1/s, **HYS** `h` = 0.5, **INT** limits ∓1e9, **PT1/PT2** `T` = 1 ms, **SDFT** a 20 ms window at 50 Hz; LIMIT stays ±1. It applies to every create (palette, scripts and the API, in the same undo step as the create); circuits you open, pasted copies and library subcircuits keep their values (`PADROES_CONTROLE` in `simu/servidor.py`). New test `blocos_controle_api` checks what the blocks do against numpy on small circuits: PT1 (Tustin, 63 % at t = T), PT2 (a1·(1 − cos t/T): no damping), PI (r0·x + a1·∫x), INT (reset at z ≥ 1, limits), PD (a pure differentiator, a1·dx/dt), DELAY (int(T/Δt) steps, 0 while filling), HYS (±1, switching at ±h), LIMIT, S-H (level), COUNTER, the comparators and logic (0.5 threshold), 19 Math blocks (POW is left to Gecko patch 0007), abc→dq→abc and TIME (which reads t − Δt in the recorded run) (#135).
- Machines: the DC machine, PM DC machine, PMSM and squirrel-cage induction machine have their terminals where Gecko puts them (wires snap, loose ends are checked) and a symbol (a circle with **M** and **=** or **~**, the type and the load torque). The motor panel picks the **load torque** from a control signal label (Gecko has no shaft: e.g. a CONST the control or a trigger changes) and names the terminals (armature ±, field ±, phases); the **Machine quantity** block (VIEWMOT) picks the machine and one of its internal quantities (speed, currents, torque, angle, flux, back-EMF), and its output gets an automatic signal name for the scope and `m[...]` (`n_MDC1`, `isa_PMSM1`). Two examples with the speed control in Python: **DC motor** (half bridge, cascaded speed and current PIs: in steady state ω = (V_a − Ra·I_a)/k to 0.02 % and Tel = T_load + fr·ω) and **PMSM** (three-phase inverter, Clarke/Park, i_d/i_q and speed PIs, SVPWM: i_d ≈ 0, i_q follows its reference, speed within 0.1 %) (#133).
- Gecko patch `0006`: the *Machine quantity* (VIEWMOT) block no longer prepends the machine name again on every reopen (`M-DC.1M-DC.1.n [rpm]`…) nor flips that field after a simulation (which made the circuit look unsaved after every run); it is always `M-DC.1.n [rpm]` (#133).
- **Scope: XY panel** (*+ XY panel*), replacing Gecko's own *Space Vector Diagram* and *U-Z\*i Diagram* windows (which MaiSim never shows). Configured in **XY ▾**, explained in its (i): *Free* plots Y against X for any two recorded signals; *Space vector* takes three phases a, b, c (guessed from names like `i_a`, `i_b`, `i_c`) and plots β against α with Gecko's amplitude-invariant Clarke (α = (2a − b − c)/3, β = (b − c)/√3), or q against d with Park by an angle θ (a signal in rad, or 2π·f·t + φ₀; negative f for a negative sequence); *U–Z·i* is Gecko's UZI block: up to two (u, i) pairs, each with its impedance Z, drawn as the point (u, Z·i) in volts on both axes (red and blue, as in Gecko). Moving average (Gecko's *Average time*), time window (whole run, last N periods, t₀–t₁, or the linked panels' time zoom), same scale on both axes, start ○ / end ● markers, an arrow from the origin, hover readout, and the time cursor of the time panels marked on the trajectory. Computed in the browser from the recorded data (also live); saved in the layout and in exported views. The examples come with it ready in their default scope layout: `exemplo_inversor_trifasico` opens with the space vector of the phase currents (αβ, and dq at f = −60 Hz, the example's negative sequence: a fixed point at |i| ≈ 14.9 A, the theory m·V_dc/2/|Z| = 14.97 A) and the U–Z·i of phase a (v_an against |Z|·i_a, |Z| = 10.69 Ω, 200 µs average), and `exemplo_inversor_ponte_completa` with the U–Z·i of its RL load (v_ab against |Z|·i_o); the simu now keeps the panel's `xy` when a default layout is saved or read. Test: `scope_xy_tela` (#128).
- Version and automatic updates: a discreet `v0.3.0` under the logo in the side rail (also in the home page's *About and credits*), whose tooltip says how MaiSim is installed (Windows installed, Linux AppImage or source code). The simu checks the GitHub Releases at startup and every 6 h (short timeout; silent when offline) and a dot on the version shows when a newer one exists on your channel (*stable*: releases only; *testing*: with the `-rc` pre-releases; semver order, so 0.3.0-rc13 < 0.3.0 < 0.3.1). Clicking opens a dialog with the release notes, **Update** / **Later** and the channel. **Update** refuses while a run is going or a circuit is unsaved; on Windows it downloads `MaiSim-Setup-<v>.exe`, checks it against its `.sha256` (refuses on mismatch), runs it silently and reopens MaiSim; with the AppImage it downloads the new one, checks the SHA-256, swaps it in place atomically and restarts; in a source checkout it only says `git pull`. Routes are local-only (`X-MaiSim` on the POSTs) (#126).
- Transfer function H(s) editable in the component panel: **numerator** and **denominator** in powers of s, written as `1 + 1e-3 s + 1e-6 s^2`, `(1 + s/100)(1 + s/1000)`, `2*0.5/1000 s` or a coefficient list from s⁰ up (`1, 1e-3`); or **poles, zeros and gain** (H = k·Π(s − zᵢ)/Π(s − pᵢ), complex as `-50+300j`, conjugate added), computed with numpy so only the polynomials are stored. The server checks them (finite, denominator not zero, degree ≤ 19, numerator degree ≤ denominator + 2; errors in pt/en) and writes `nominatorPolynom`/`denominatorPolynom` into the block through the file, as for the meters (`editor/mede` type `H`), with undo; the block shows H(s) under it (`1/(1+0.001s)`), and Gecko's dialog-only *gain* and *usePolynoms* are hidden. Tests `tf_api` (TF 1/(1 + τs) = PT1 = 1 − e^(−t/τ); 2nd order ζ = 0.5: peak 1.163 at 3.628 ms as the formula; POW x^y vs numpy; save and reopen) and `tf_tela` (#137).

### Fixed
- Dropdowns: every select in MaiSim (simu ⚙, control, component panel, AI chat, scope header A/B, the update dialog) now opens a MaiSim-styled list instead of the browser's native one (rounded, page colors and dark theme, ✓ on the chosen option, scrolling, keyboard: arrows/Home/End/PageUp/PageDown, Enter/Space, Esc, type-ahead; follows MaiSim's zoom). It is a light layer in `maisim-dica.js` over the real `<select>`, which keeps its value and fires `input`/`change` as before; `multiple`/`size` lists, disabled selects, touch input and `data-nativo` keep the native list. The old `appearance: base-select` rule never applied, since the global `appearance: none !important` overrode it. `exemplo_buck_termico`: the diode now has a junction heat capacity (`Cth.2`, 1 mJ/K, τ = 4 ms), so `Tj_D1` rises smoothly to ≈ 47 °C instead of following every loss pulse (spikes of ~350 °C) (#131).
- Integration method (⚙): it is now part of the circuit, like a global variable. Choosing it in ⚙ applies it to the circuit right away (new `POST editor/solver`), so Save writes what ⚙ shows even without a run, the change marks the circuit as unsaved and Ctrl+Z undoes it; before, the choice lived in the browser and reached Gecko only when a run started. **New** circuit goes back to backward Euler (Gecko's CLEAR kept the previous model's method, and the page reported it as "from the file"). Comparar says "may differ" when one MaiSim run predates the field. Only the integers 0, 1, 2 are accepted (`true` and `1.9` were taken as 1).
- Thermal and losses, from the review of #119/#130:
  - a Gecko still running a jar without patch 0005 (rebuilt but not restarted) no longer fails every run with a loss signal: the motor detects "unrecognized method hash" and averages step by step itself (same values);
  - the control code's `m[...]` gets the loss signals (FLOW) as the average over the last Ts, not the step value (which was 0 almost always and E/Δt on a commutation step); temperature stays point-sampled; the guide, the skill and the AI context say so;
  - the loss average uses the steps Gecko actually took if it stops in the middle of a stretch (with a run warning);
  - thermal (and reluctance) subcircuit terminals get a pin, snap to the border and become a block pin, so a thermal network can cross a subcircuit;
  - TEMP refuses a label that is not a thermal node; a Pv can heat a circuit resistor (i²R) and a FLOW can measure the heat flow of an Rth, Cth, heat source or DT, as in Gecko;
  - automatic names follow the Pv (re-coupling it renames its FLOW/TEMP outputs); a TEMP against a node other than the TREF is `Tj_<part>_<ref>`; a heat flow is `P_<element>`;
  - a semiconductor in Gecko's detailed loss mode (`.scl` curves) shows that the simple fields do not apply;
  - tests: Gecko's own `BuckBoost_thermal.ipes` against Gecko stepped alone, a heat source inside a subcircuit, the example's Tj checked on the rise (Tj − 25 °C) instead of the absolute value.
- Loss signals in the scope: Gecko's switching loss (a FLOW measurement with `losscomp switching`) is E/Δt on the single step of each commutation, and the run kept one point sample every N steps, so the scope almost never caught it — on `exemplo_buck_termico` `Psw_IGBT1` averaged 0.000 W (nonzero in 1 of 4001 samples) and `Pv_IGBT1` equalled `Pcond_IGBT1`. Now every FLOW signal (identified by the element type, not the name) is recorded as the **average over its sampling interval**: the motor's new `STEPA` reads them after every step inside Gecko (Gecko patch `0005`, `simulateStepsAveraged`; with an older jar the motor falls back to stepping one by one), in runs with and without the Python control. `Psw_IGBT1` now averages 1.265 W (the per-step sum gives 1.266 W) and `Pv = Pcond + Psw` in every sample; other signals (PWM, voltages, Tj) stay point-sampled and unchanged, and the control's `m[...]` still gets the point value. The run's `meta.media_intervalo` lists the averaged signals and the scope legend marks them "(interval average)" (#130).
- Gecko patch `0007`, broken control blocks: **POW** (x^y) now really has two inputs (its calculator was created with one, so the second input did nothing and a run threw `ArrayIndexOutOfBoundsException`); the **transfer function** divides its second-derivative term by Δt² (it was Δt, so a numerator two degrees above the denominator lost its s² part: (1 + s/ω₀)² on sin ω₀t now gives 2cos ω₀t to 1e-3); the TF dialog's poles/zeros → polynomial conversion (`PolynomTools`) adds the imaginary parts correctly (complex roots after a real one gave wrong coefficients) and trims by magnitude without running past index 0 (a negative gain crashed it); the polynomial-division remainder is never longer than the denominator. **DELAY** rounds T/Δt with a tolerance (T = 70 µs at Δt = 10 µs gave 6.999… and delayed 6 steps; now 7). A new TF is 1/(1 + 1e-3 s) in polynomial mode (it was 1/1, and Gecko's dialog in pole/zero mode rebuilt it as (s − 1)/(s − 2)); saved circuits keep theirs. Rebuild Gecko (`bash gecko/construir.sh`) (#137).

## [0.3.0] - 2026-10-25

### Added
- Closing the MaiSim window stops MaiSim (the window opens on an "Opening MaiSim…" page with the pulsing diode until Gecko and the engine are up — before, the home page asked the engine while it was still starting and kept "no editor engine"; launcher with `--abrir`, the installer and AppImage shortcuts): every page sends a heartbeat to the page server every 15 s (`/maisim/vivo`) and a beacon when it closes; once no page is open (20 s after the last close, 45 s for a page that went silent, longer for a hidden or frozen one), the launcher stops servers, engine and Gecko like `--parar` (Gecko stays if a circuit is unsaved, and the next launcher adopts it). It waits for a run in progress to finish. Clicking the icon while MaiSim is still up just opens the window on it. When closing will stop MaiSim, the simu asks first if there are unsaved changes. `MAISIM_NAVEGADOR` picks the browser (`nenhum`: none) (#104).
- Take a circuit to another MaiSim: **Export** on each row of the home page's Circuits section saves a `.msd` (a zip with a `manifest.json`: format version, every file with its SHA-256) holding the circuit, its control code, appearance and default scope layout, and the runs you tick (none by default, with the estimated size). **Import…** shows a preview (who exported it, when, with which MaiSim; the runs, all ticked; a name conflict offers `<name>_2`, replacing needs a confirmation) and then writes the circuit to your circuits and the runs to the runs folder, rewriting their `meta.modelo` and `resumo.md` so they stay linked to the new circuit. No source-machine path goes into the file; paths with `..`, absolute paths, backslashes, unknown extensions, a SHA mismatch, over 1 GB / 5,000 files or a newer format version are refused before anything is written. Export warns when the circuit points to an external file (#102).
- CI: each new version's Release gets the Linux AppImage and the Windows installer, with their `.sha256` (`packages` workflow, started by the full suite right after it creates the Release; also runnable by hand with a tag). A `-rc` version is published as a pre-release (#99).
- Linux AppImage: `pacote/linux/monta.sh` builds `MaiSim-<version>-x86_64.AppImage` with a portable Python 3.11 + NumPy, a Temurin 11 JRE (both pinned and SHA-256-checked), Gecko with its patches, the compiled editor engine and the local Monaco; it opens through the launcher in the produto profile (data in `~/MaiSim`). Only Xvfb is needed from the system (#97).
- Windows installer: `pacote/windows/monta.sh` builds `MaiSim-Setup-<version>.exe` (Inno Setup in docker) with the embeddable Python 3.11 + NumPy, a Temurin 11 JRE (pinned and SHA-256-checked), Gecko, the compiled engine and the local Monaco. Per-user install with no admin, pt/en wizard with MaiSim's images: where to install, where your circuits are kept (Documents\\MaiSim), the port (checked against what is already listening, e.g. a MaiSim in WSL), shortcuts (open, stop, my circuits folder), credits; uninstalling asks whether to also delete your data (default: no). The launcher finds the bundled Java (#98).
- `app/lancador.py`: one launcher for Linux and Windows (what the packages will run): starts the page, scope, simulator, Gecko (in Xvfb on Linux) and the editor engine, waits until ready, opens the browser as an app (`--abrir`), and on Ctrl+C or `--parar` stops what it started, leaving Gecko up if a circuit is unsaved (or when that cannot be known; `--forcar` stops it). With `--produto` it uses the produto profile. A fresh Gecko starts on a blank sheet when nothing is open (#94).
- Config profile `produto` for the upcoming Windows installer and AppImage (`MAISIM_PERFIL=produto`): data in a visible folder (`Documents\\MaiSim` on Windows, `~/MaiSim` on Linux), cache in the system's place, and a personal config file on top (`%APPDATA%\\MaiSim\\maisim.env` / `~/.config/maisim/maisim.env`) where the installer writes the chosen port and folders. The developer setup is unchanged (#92).
- Home page, Circuits: a delete button on your circuits (not on the one open in the editor). After a confirmation it deletes the circuit for good, with its control code and colours, so nobody has to find the folder (#87).
- Home page: a **Circuits** section. *Recent* lists the circuits opened last (the simu notes every open and save in `recentes.json`), *All circuits* lists yours, the library and the extra folders by group, with search; one click opens a circuit in the simu, and the folder where your circuits are kept is shown (#85).
- CI: when the full suite passes on main, every PR merged since the last green run gets a comment saying so (with the run link), and the READMEs show the verify and full-suite status badges (#84).
- `MAISIM_PORTA=8100` in the `.env` moves all seven ports at once (8100–8106, display :81), like `npm run maisim -- -p 8100` but for good; a port written separately still wins (#86).
- Simu properties panel: Gecko parameters that are a choice show as one. The signal source shape (SIGNAL, FILE, RANDOM) is a list (Sine, Triangle, Rectangle, Random, Import; Gecko stores 402–406), every source type (U, I, MMF, HEAT-SOURCE, DT) too, and Gecko's yes/no parameters (useExternal, display…) are checkboxes. Typing `$` in a parameter that takes a global variable lists the circuit's variables with their values, filtered as you type (↑/↓, Enter or Tab, Esc, click) (#70).
- **Scope: Power in Measure.** A *Power* mode pairs each voltage with its current by name (`v_a` with `i_a`; pick other pairs in the lists), draws p(t) = v(t)·i(t) as a curve with its legend entry, and gives P, V_rms, I_rms, S, λ = P/S and the fundamental P₁ and Q₁ over the Fourier window (#68).
- Simu: put a signal in several scope panels, and delete panels, right from the signal's panel picker (#67).
- Simu tests: `simu/validacao/vistoria_componentes.py`, an on-demand survey of the 121 palette components on the test instance (each one alone on a new sheet: inserted as the palette does, its parameters read, a short run), written to `simu/validacao/tmp_vistoria/` as JSON and a Markdown table (#77).
