# Validação do Controle (MaiSim / simu)

**Num comando só:** `./ci.sh rapido` (o que a verificação de cada PR roda no GitHub Actions), `./ci.sh completo` (a
bateria inteira, que roda depois de cada merge no `main`; `./bateria.sh` é o mesmo) ou `./ci.sh <teste>…` — com a
instância de teste no ar (`./sobe_teste.sh`). Ver `CONTRIBUTING.md` na raiz.

Estes são os ensaios que sustentam os números do `GUIA_CONTROLE.md` e do `HISTORICO.md` (passos 1, 2 e 2b do Controle). Todos
rodam numa **instância de teste** isolada, que não mexe no Gecko nem no scope do MaiSim:

| Peça | Endereço |
|---|---|
| tela virtual | Xvfb `:72` |
| Gecko | porta 7203 |
| motor | porta 7204 |
| servidor do simu | porta 7201 |
| arquivos | `~/.cache/maisim_teste/` |

```bash
cd simu/validacao && ./sobe_teste.sh
```

```bash
cd simu/validacao && ./desce_teste.sh
```

Rode um ensaio por vez, porque o Gecko de teste é um só. Os ensaios Python usam numpy, e os de tela usam o Playwright
(`NODE_PATH` apontando para um `node_modules` que o tenha).

## Reiniciar só o servidor de teste

`reinicia_servidor_teste.sh` (re)sobe só o servidor do simu da instância de teste (7201), com o ambiente dela. O
`sobe_teste.sh` e os testes que reiniciam o servidor (`nao_salvo_api.py`, `tela/validador_tela.js`) usam este script;
antes, usavam um script na pasta temporária de uma sessão, que some com ela. O Claude do MaiSim da instância de teste
**nunca** usa o login de verdade: pasta descartável `~/.cache/maisim_teste/claude-maisim` (o `desce_teste.sh` apaga) e
o claude de mentira. Antes, o `sobe_teste.sh` não definia a pasta, e o teste de login, que clica em "sair", teria
desconectado o Claude do MaiSim de verdade.

`reinicia_gecko_teste.sh` (re)sobe só o Gecko e o motor da instância de teste (7203 e 7204, pelos PIDs dessas portas), com o modelo da partida (noutro grupo de processos, `setsid`); o simulador e a tela virtual ficam; sai com erro se o Gecko ou o motor não ficarem prontos. O `sobe_teste.sh` e o `gecko_novo_api.py` usam este script.

## Pedir ao Claude sem gastar a conta

O servidor de teste sobe com `MAISIM_CLAUDE_BIN=<esta pasta>/claude_falso.py` e `MAISIM_CLAUDE_DIR` numa pasta descartável. O
`claude_falso.py` imita o stream-json do CLI 2.1.273. O cenário (ganho, metade, perigo, quebra, json_ruim, lento, anexo,
erro, recusa) vem do arquivo `falso_cenario` nessa pasta, e `falso_logado` faz o `auth status` dizer conectado. Login e
logout vão para o CLI de verdade (o `claude_tela.js` continua valendo). Cada chamada fica em `falso_chamadas.jsonl`,
para conferir as opções.

O Cursor do mesmo jeito: `MAISIM_CURSOR_BIN=<esta pasta>/cursor_falso.py` e `MAISIM_CURSOR_DIR` numa casa descartável (a
HOME do `agent` de mentira). O `cursor_falso.py` imita o Cursor CLI 2026.10.22 (o stream-json da documentação, os comandos
login/status/models/logout e as mensagens de erro) e aplica a mesma política de permissões do `agent` (negado > permitido;
sem `--force`, escrever fora da pasta e o terminal são negados). Cenários em `falso_cenario` (ganho, le_conversa, terminal,
fora, erro, limite, sem_login, lento, resumo_falha); `falso_login` (ok, erro) é a página do Cursor autorizando ou recusando.
O registro (`falso_chamadas.jsonl`) guarda os nomes das variáveis do ambiente e se havia chave — nunca a chave.
`cursor_offline.py` confere a peça sem servidor; `cursor_api.py`, o login, o pedido, a sessão, as recusas, os erros, o
resumo, sair e a chave de API; `tela/cursor_tela.js`, a seção do Cursor na janela das contas.
